# pixel-redraw：AI 參考原圖 → 遊戲像素素材

這套做法是 2026-11-17 跟使用者一輪一輪試出來的，每條規則後面都有「為什麼」。**照順序做，不要跳步，也不要自己加使用者否決過的步驟。**

## 0. 先知道的事

- **原圖是假像素。** AI 畫的是被不整齊放大的像素畫，格子是小數，而且寬高常常不同（例如 6.2、4.02×5.32）。所以要照它自己的格子讀回。
  - 固定倍率縮圖會糊。
  - 用程式重畫（codeart2d、pixelfx 重新上色、逐物件重畫）都試過，使用者說「蠻糟糕」「細節不見」「偏離原圖」。
- **工具**：agent-sprite-forge（MIT，0x0funky）的 skill 已裝在同一個 `.claude/skills/` 底下：`generate2dsprite`（pixel_look、pixel_reduce、palette_tool）、`codeart2d`（pixel_qa、_pixel_perfect）等；要用別的位置就設環境變數 `ASF_SKILLS`。本 skill 的腳本在 `scripts/`，都是 `python 腳本 --help` 看得到用法。需要 numpy、Pillow、scipy。
- **資料夾**：
  - `art/1-參考原圖/`：原圖。
  - `art/2-草稿/<名稱>-look/`：工作資料夾。
  - 使用者說通過後，存到 `art/2-草稿/<名稱>/通過-日期/`。
  - 使用者說「接進遊戲」才複製到 `art/3-已通過/`，接著改遊戲程式。
- **給使用者看**：
  - 一律用「原圖／現在遊戲／新版」放大並排的圖（最近鄰放大），用 SendUserFile 傳。
  - 自己看截圖覺得「可以」不可靠。
  - 使用者用手機看，說明用繁體中文、短句。

## 0b. 生新圖：尺規參考圖

- AI 不會照尺規要求的像素大小畫。例如要它畫 11 px 一格，它實際畫成約 9.4 px，細節更細。所以尺規的方塊大小要設成 AI 自然會畫的大小（約 9 px），**物件的畫布預留 32×32**（使用者 2026-11-17：「大一點沒關係」）。
- 尺規圖裡放一個**已經通過的同類物件**（放大成同樣的方塊大小），讓每一批都對齊同一個像素大小。不要每批換一個新的尺。
- 提示詞與尺規放在 `docs/美術/提示詞-道具.md`、`art/1-參考原圖/items/`。

## 0c. 色數上限：依類別、每個物件各自算（使用者 2026-11-17 定，數字由我設計）

| 類別 | 每個的上限（含外框黑） |
|---|---|
| 道具圖示（背包、裝備、垃圾、材料） | 16 |
| 場景小物件（石頭、木箱、路燈）／可互動物件（寶箱、機關） | 16（花草這種單一材質 12） |
| 建築 | 32 |
| 主角每個形態、NPC | 16（同一角色所有動作共用一套） |
| 雜兵怪物 | 12 |
| 菁英、王 | 24 |
| 特效 | 8 |
| 介面圖示、按鈕 | 12 |
| 場景視差層 | 整關共用 24；背景 ≤8、遠景 ≤8、中景 ≤12、近景 ≤12、前景 ≤10、地面／平台 ≤16 |

物件表**不限整張總色數**。整張 24 色時，十幾種材質每種只分到兩三色，顏色會跑：鐵核的黃光變紅橘、石頭變紫灰。

## 1. 小物件表（一排或幾排物件的圖）

**新做法（格子圖、新生的圖都用這個）：**
```bash
python scripts/scene_grid.py art/1-參考原圖/items/cores.png                       # 量整張的格子
python scripts/props_read.py --src .../cores.png --name cores --cell 9.4 --key "#ff00ff" --ruler 26 25 --work art/2-草稿/xxx
python scripts/items_finish.py --name cores --colors 16 --sym 0 1 2 --multi 7 --work art/2-草稿/xxx   # 每個物件各自處理
```

### 檢查流程（使用者 2026-11-19 定：照網上的像素畫規則量化；**畫完自動修，不用給使用者檢查**）

| 關 | 檢查 | 怎麼量 | 處理 |
|---|---|---|---|
| 讀回 | **5 像素大小一致** | 第 0 格的金幣是尺，讀回大小跟標準（26×25）比 | 差超過 8% → `WARN`（這批要重生或接受，自動修不了） |
| 形狀 | **4 外框外的分開光點** | 主體以外的分塊 | 小於 12 格一律拿掉；不是「多塊」物件就只留主體（`--multi` 列出多塊物件，例如斷成兩截的魔杖） |
| 形狀 | **1 斜率**、**2 曲線單調** | 剪影四個方向的階梯段長 | 斜直線段長要一樣（1:1、1:2、2:1）；曲線一路變長或變短，轉折那階（圓最凸的地方）最長；不合就往內挖或補色重排 |
| 形狀 | **3 對稱** | `--sym` 列出設計上左右對稱的物件 | 右半邊照左半邊（受光面）鏡射，顏色保留右邊自己的；要改的格子超過 6% 就不改（AI 本來就畫得不對稱，硬鏡射會變形） |
| 形狀 | 外框一層、無 L 形、無單格凸凹、外框內無暗格 | `outline2.check` | 外輪廓重建（見下） |
| 顏色 | **6 灰階明暗＋雜點**（同一類問題） | 單格、跟周圍都不同色，灰階又跟周圍差 < 0.08 ＝真雜點；相鄰不同材質灰階差 < 0.05 ＝糊在一起 | 真雜點併成周圍色（灰階差很多的單格＝鉚釘、眼睛、高光，保留）；糊在一起的兩色往亮、暗推開 |
| 顏色 | **10 色相偏移** | 同材質色階由暗到亮 | 暗部往藍紫、亮部往黃推（最多 10°） |
| 顏色 | **8 枕頭式陰影** | 亮度跟「離外圍距離」的相關，減去跟左上光源的相關 | 大於 0.25 → `WARN`（要重畫，自動修不了） |
| 顏色 | **9 帶狀** | 兩色交界連續 4 列以上對齊成直線 | **只計數不改**。自動每隔一列錯開會變成虛線鋸齒（試過：水桶邊、鐵靴變難看）；直的交界很多是刻意的（鐵盔護鼻） |
| 顏色 | **7 剪影** | 塗成單色、放黑白灰底 | 外框是近黑，黑底一定看不見，由選擇性外框 shader 處理（使用者正在做），不算錯 |

- 對稱、多塊要在提示詞表格標出來（「對稱」「多塊」兩欄），跑 `items_finish.py` 時照表格給 `--sym`、`--multi`。
- 使用者指出、已經手修過的物件放在 `hand-<name>/<name>-<i>.png`：重跑時從手修版接著檢查，不會被蓋掉。
- 結果每個物件印一行：`outline`（形狀檢查，要全 0）、`fixed`（每項自動修了幾處）、`pillow`（枕頭式分數）。`WARN` 只會是：像素大小不一致、枕頭式陰影、外框檢查不是 0、沒預期的大量少格或跑色（手修、拿掉光點、對稱造成的不算）。
- `items_finish.py` 每個物件各自做這幾步：
  1. 學自己的色盤。
  2. 拿掉小於 3 格的碎塊。
  3. **外輪廓重建（`outline2.py`，使用者 2026-11-19 教的做法）**：
     - **不在原本的黑邊上修補**：剝掉外圍那一層黑邊，得到物件本體。
     - 本體剪影照步進修：平邊上單格凸起往內挖掉、單格凹陷在內層補上旁邊的色、斜邊階梯長短不規律就重排、曲線段長要單調（轉折那階同時算在兩邊，不然圓會變成六角形，2026-11-19 金幣試過）。
     - 外面包**一層**外框黑（上下左右緊貼本體的格子）。外框永遠只有一層，斜邊自然是一格階梯，不會有直角雙層、一堆黑點。
     - 外框出現 L 形時，把轉角補成本體。
     - 貼著外框、亮度很低的本體格（看起來像第二層黑）調亮成較亮的近似色。
     - 只剝一層：剝兩層會把星星尖角、光芒削短。
     - 檢查用「看起來是黑的就算」：外框多出來或缺的、L 形、單格凸凹、不規律階梯、外框內緊貼的暗格，全部要是 0。
     - 2026-11-19 前的 `outline.py` 只認那一個外框色，檢查是 0，使用者卻還看得到直角和兩層黑，所以改掉。
  4. 內部的黑換成材質最暗色（在外輪廓重建之前做）。
  5. 壓回上限。
  6. 自動比對讀回與最後結果（先對齊再比）：沒預期的少格超過 6%、或顏色平均偏移超過 0.10，就印 `WARN`。
- 它也會輸出 `stages-<name>.png`（每一步並排），我自己看過、修到沒有 `WARN` 為止，**不用再給使用者檢查**（使用者 2026-11-19：「畫完自動修不用給我檢查」）。
- **不要再用 `pp_fix`（完美一格線）處理 AI 新圖。** 它把所有暗色都當成線，深色物件（暗影、隕鐵）整個被削成蜘蛛腳；小閃光還會被強制加框，變成一顆顆黑點（2026-11-17 使用者：「外框有破碎的單格像素」）。
- **底色選這批物件沒用到的顏色**：有紫、粉紅時用綠 `#00ff00`，有綠時用藍。`--key` 要跟著改。
  - 去背只挖很接近底色的格子。舊的洋紅判斷會把紫色光暈、粉紅當成底色挖掉（使用者：「圖裡面被你切掉了」）。

**舊做法（2026-11-17 以前那批一排的原圖，已通過的就不用重做）：**
```bash
python scripts/props_read.py --src art/1-參考原圖/props/rocks.png --name rocks --work art/2-草稿/xxx
python scripts/props_finish.py --name rocks --colors 16 --work art/2-草稿/xxx          # 有外框
python scripts/props_finish.py --name moss --colors 12 --no-outline --align top --work ...   # 沒外框、往上掛
```

1. **先量整張圖的格子，用同一個格子讀每個物件。**
   ```bash
   python scripts/scene_grid.py art/1-參考原圖/items/cores.png          # 例：x 9.3、y 9.6 → 用 9.4
   python scripts/props_read.py --src .../cores.png --name cores --cell 9.4 --work ...   # 幾排的格子圖也能切
   ```
   - 一張圖裡的物件是 AI 用同一個格子畫的，所以要用同一個格子讀。
   - 讓 `pixel_look` 每個物件自己判斷的話，細長、尖角、有煙的物件會被誤判成更細的格子（6～7 px），讀回來變大又糊，每個大小也不一樣（2026-11-17 星核：22～42 px 不等，使用者問「你有照 skill 嗎」）。
   - 改用共用格子後，12 個都落在 22～29 px。
   - 只有一排、物件格子明顯各不相同的舊原圖，才不給 `--cell`，改用 `pixel_look master --proportions blocks`。
     - 要用 `blocks`：用 `picture` 的話，複製出來的那列線會變兩格粗、斜線會抖。
     - 報錯「cells are only about N px」，就用 `--x 3` 重讀那幾個（`--only i`）。
2. **每張表一套色盤，上限 24 色，不一定要用滿。**
   - 太接近的色會合併。使用者說過色數太多會「太雜亂」，像素畫要適當簡化，不必完全忠於原圖。
   - 不同類的表不要硬共用一套色盤，藍、紅這些少數色會被擠掉。
   - 只出現在單一物件上的重點色用 `--reserve` 加回，例如路燈的亮黃星星。
   - 道具圖示一張有十幾種不同材質，24 色很緊。苔蘚綠、粉紅、紫光這種少數色，一定要先從讀回結果（`L-`）挑出來 `--reserve`，不然會被吸成金或灰。
   - 光芒、火花、粉塵、彗尾這些本來就分開的小塊，要加 `--keep-parts`。不加的話會被當成碎片刪掉。格子圖物件之間空很寬，不會有隔壁物件切進來。
   - 套完外框規則超過 24 色時，用 `cap24.py` 併回去。
3. **外輪廓輕修。**
   - 跑完美一格線 `pp_fix` 和外輪廓抖動修平 `flatten`，然後用 `pixel_qa` 看 L 形直角和外圍缺口。
   - 小草、苔藤這類 `--no-outline`，混進來的洋紅要清掉。
4. **套外框規則**（見第 3 節）。

## 2. 場景視差層（背景、遠景、中景、近景、前景、地面、平台、霧）

```bash
python scripts/scene_grid.py art/1-參考原圖/valley/*.png         # 先量每層的格子
python scripts/scene_read.py --src .../near.png --name near --cell 6.47 6.47 --period 6 --up 2 --work art/2-草稿/xxx
python scripts/scene_fit.py --src read/near.png --out fit/near.png --mode split    # 背景 crop、地面平台 bbox
python scripts/derim.py --src fit/fg.png --out fit2/fg.png --k 5                  # 有細亮邊的層才跑；其他層直接複製到 fit2
python scripts/scene_recolor.py --src fit2 --out rc --colors 24 --reserve "#c18d2f" "#f3b84e" "#0d83aa" "#2ddeea" \
    --layer back=6:far far=8:far mid=12 near=12 fg=12 ground=14 platform=12
```

1. **量格子。** `pixel_reduce` 自己的偵測在這種圖上常常不準，例如量出 25、32 這種數字，不要直接信。用 `scene_grid.py` 兩種量法交叉看；差兩倍時，放大原圖用眼睛確認。
2. **照原圖格子讀回。**
   - 格子是小數或寬高不同時，先最近鄰縮到整數格再讀。
   - **前後大小要對**：每層各自照原格讀回後，近景常常比中景還小，前後感就反了。這時把近景、前景讀回後整數放大 2 倍（`--up 2`），像素仍是整齊的方塊。
   - 不要用非整數格硬讀成某個高度，例如每 3.35 格讀一格，那樣格子會一下 3 一下 4，造成抖動。
3. **調高度**（遊戲畫面 216 高）：
   - 垂掛＋地上的層：中間空的列抽掉或補上。
   - 背景：上下裁。
   - 地面、平台：裁到有像素的範圍。
   - 原圖多出來的雜邊要清掉，例如地面上緣的灰白霧邊。
4. **細亮邊線拿掉。** 岩石、葉子邊上的細青色亮邊，讀回後會斷成虛線，使用者說要修掉。
5. **整關共用一套色盤，24 色以內**（`scene_recolor.py`）：
   - 越遠的層色數越少；遠的層不准用亮的重點色。
   - 重點色（金、青、青綠……）用 `--reserve` 固定保留，而且只給原本就是這個色的格子用。
   - 配色要看色相和彩度，不能只看距離。只看距離時，藍蘑菇長出金斑、灰石頭變鮮藍、樹皮亮面變刺眼的金。
   - 地面跟其他層色系不搭時（藍灰 vs 紫），可以先把色相轉過去再學色盤。
6. **到這裡就停。** 給使用者看粗略合成圖，記得說明沒有遊戲裡的打光和遠景變暗。

## 3. 外框規則：外輪廓只能黑、內輪廓禁止黑（使用者 2026-11-17 定）

```bash
python scripts/blackline.py <來源資料夾> <輸出資料夾> <表名>
python scripts/cap24.py <套之前的圖> <套之後的圖>      # 超過 24 色時把新加的深色併掉
```

- 黑色統一用近黑的深藍紫 `#11102e`，不是純黑。
- 外圍一圈的深色，包括每張表自己的外框線色，例如 `#211f41`，全部換成這個黑。
- 物件內部的黑線換成所在材質最暗的一階，例如木頭用深棕、石頭用深灰紫、菌褶用深米褐。材質本身沒有更暗的一階時，自動加一階深色。
- 有外框的物件、建築、平台都適用。場景層本來沒有外框，不適用。
- 副作用：靠黑線畫的細節會變淡，例如木箱裂縫、輪胎破洞、灌木的葉片分層。要告訴使用者，必要時那幾處改成「比材質最暗再暗一點、但仍不用黑」。

## 4. 逐處手修

- **只修使用者指出的地方。** 加座標格或放大給使用者指位置，一處一處改（`spotfix.py`），改完用 `sheet.py` 重排物件表。
- **改之前先放大並排原圖，看那裡原本該是什麼色。**
  - 色盤裡缺那個材質的顏色時，例如菌褶的米褐被吸成綠，要照讀回的原樣（`L-` 資料夾）把正確的顏色加回來。
  - 不要只換成周圍的顏色。那樣做過一次，結果變成一團暗紅，被說「顏色不對」。

## 5. 使用者否決過、不要再做的事

| 做過的事 | 使用者的反應 |
|---|---|
| 讀回後用程式做全圖自動清理（降色＋清碎片＋修色塊步進 tidy/steps） | 「方向錯了」，圖會變平、少了質感 |
| 刪過渡色、併色階（苔蘚 6→3 階、紫岩 9→6 階） | 「方向錯了」 |
| 把 1～3 格的同色碎塊自動換成周圍色 | 做完又說「還是不要修破碎色」，已通過的那批也退回 |
| 固定倍率縮圖＋去雜點、codeart2d 程式重畫、pixelfx 重新上色、逐物件逐像素重畫 | 都說糊、細節不見、偏離原圖 |
| 前景太高時裁掉地上蕨類的上半 | 要改裁垂掛部分的最上面 |

- 存到 `art/2-草稿/<名稱>/通過-日期/`，連同色盤，並記下接進遊戲時要改的地方：每格大小、地面高度、平台碰撞、光源位置。
- **使用者說「接進遊戲」才動 `art/3-已通過/` 和遊戲程式。** 動之前先確認，動完要匯出、建置、截圖給使用者看。
