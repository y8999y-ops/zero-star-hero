# scene-fx：場景環境特效

從 2026-11-17 做碎星鎮雨天積水開始累積。每條規則後面有「為什麼」。**畫圖、做特效還是要先載入 pixelfx skill，照它的「畫→看→修」至少三輪。**

## 0. 先知道的事

- **畫面主體是 CPU 算的，重的逐格效果交給 shader（混合，見 §6）。** 每格畫進 `Frame`（`unity/Assets/Scripts/PixelFX/Painter.cs`）：
  - `Color`：顏色（不透明）。
  - `Light`：加上去的光。讀寫前它會先把還沒畫的光暈畫完。
  - `Ox`、`Oy`：鏡頭位置。世界座標要減掉它們才是畫面座標。
  - 解析度 384×216，城鎮地面 `TownArt.FLOOR = 184`。
- **影片裡的東西怎麼換：**
  - Godot 的 SubViewport／螢幕貼圖：先 `Array.Copy` 一份 `Color`／`Light`，再從那份取樣（`TownPuddles` 的 `srcC`、`srcL`）。
  - shader 的 step()：每一欄或每一格算一個門檻，比大小。
  - GPU 粒子：自己用 List 存的小粒子，或 pixelfx 的純函式迴圈特效（`Fx/TownRain.cs`）。
- **橫向卷軸，不是俯視。** 影片多半是俯視角，地面是一大片。我們的地面只是一條 6 列高的草皮帶（城鎮第 185～190 列），從側面看：
  - 積水＝草皮帶上扁扁的橢圓，中間厚、兩頭收成一條線。
  - 倒影＝把地面上方的畫面翻過來、**壓扁**（`SQUASH` 約 2.6）。不壓扁的話，6 列只映得到腳底。
  - 漣漪＝從側面看到的環＝兩小段往左右滑開（pixelfx weather/rain 的 `rings`）。
- **只做 Unity 版、不比對網頁版**（2026-11-12 起）。新特效寫在 `unity/Assets/Scripts/Runtime/…`，檔頭註明「Unity 版自己的」。
- **畫的順序**在 `Game.cs` 的 Step 繪圖段：場景 → 怪 → 主角 → 前景特效 → `TownArt.DrawWeather`（雨 → 積水）→ `DrawFg` 前景草葉、四角壓暗。
  - 要映出角色的東西（倒影），一定要畫在角色之後。
  - 會被霧蓋掉的東西，要畫在霧之後。
  - 雨的貼地薄霧使用者說效果不好，已經取消（2026-11-19），不要再加回去。

## 2. 積水（已做，`Runtime/Town/TownPuddles.cs`）

- **形狀**：`Field(x)` 是兩層一維雜訊，門檻 `thr = 0.74 - 0.27 * wet`，下滿雨約 4 成地面有水。
  - 深度＝(雜訊 − 門檻) / 0.15。除數太小，水窪兩頭會收得太硬。
- **濕度 `wet`**：
  - 下雨約 40 秒積滿，雨停約 90 秒乾掉。
  - 進場時（`Reset` 後第一格）直接等於現在的雨量。不然玩家一進城鎮看不到積水。截圖工具也要在設好天氣之後 `TownPuddles.Reset()`。
- **倒影**：越遠的列反射越多，越近的列越看得到水底（比較暗）。漣漪附近左右晃，晚上把 `Light` 一起映進水裡（路燈、窗戶）。
- **邊**：
  - 遠邊：亮邊，跟著兩層移動雜訊斷斷續續。只用一層高頻雜訊的話，會變成規則的虛線，很死板。
  - 遠邊還有滑動的反光點。
  - 近邊：暗線。
  - 水窪底下一列草皮壓暗。
- **踩水**：`TownPuddles.Player` 每格由 Game 叫。在水裡每走 9 px 起一圈大漣漪，濺起 4～6 顆水珠。

## 3. 慢慢變濕、積雪（照影片 05 的雪，再加上水會流）

**同一套遮罩：** `濕(x, y) = 雜訊(x, y) + 偏移 > 門檻(wet)`。門檻隨濕度往下降，就會從「幾點」長成「一片」。雪是堆積，水會流，所以偏移不一樣：

- **雪**：朝上的面最先積，偏移＝「朝上程度」。往上那格是空的，這格就是朝上的面。
- **水**：
  - 從受雨的頂面開始（偏移最大），沿著牆往下越來越淡，所以要減掉「離頂面的距離 × 斜率」。
  - 雜訊在 y 方向拉長（例如 x/3、y/12），看起來是往下流的水痕，不是一團一團。
  - 屋簷、凸出的邊下面那幾格多加一點（水從那裡滴下去）。
- **雪與濕的樣子**：
  - 濕：原色變深一點、飽和一點，朝上的邊加一條濕亮的反光。
  - 雪：直接換成雪色，邊緣用 2 色階。
  - 都要像素化：遮罩以整格計算，不用半透明漸層。
- **效能（手機要跑）**：
  - 遮罩只跟「濕度」和「靜態圖層」有關。建築圖層載入時算一次「頂面距離」「朝上程度」存成 byte 陣列；濕度每變 1/32 才重算遮罩（存 byte 陣列），平常每格只查表。
  - 每格的迴圈只跑畫面內的那幾欄；不要每格 new 陣列（`Prof.Bytes` 會記暫存）。
  - 整個畫面的逐格運算用 `PixelFX.Par.For(8, …)` 切 8 段，每段只寫自己的列。

## 4. 雨跟房子、物件互動

- **已做（`Runtime/Town/TownRainHits.cs`，2026-11-19）踩到的坑**：
  - 從頂面往下算「淋得到」時，碰到**短的空隙**（屋頂上的小香菇、圖裡 1～2 格的縫）不能當成被擋住，否則會整條直的不濕，看起來一條條色差；空隙 6 格以內跳過去，長的才算屋簷下。
  - **外框（暗色，RGB 加起來 < 150）不碰**：濕亮邊畫在頂面往下第一個不是外框的像素，不然會把黑色外框改成亮色（違反「外框黑」）。
  - 變暗不要太多（×0.87 左右，飽和 ×1.12），不然整棟像晚上。
  - 濕度跟積水共用 `TownPuddles.Wet`，所以地上和房子一起濕、一起乾。
  - 除錯：`WeatherShot` 會輸出 `score.png`（世界座標的變濕分數，紅線＝接雨面），用來找「哪幾欄為什麼不濕」。`SHOT_WET=0.25`／`0.55`／`1` 看慢慢變濕。


- **接雨面**：載入時從建築圖層（城鎮 `MAIN`）每一欄由上往下找第一個不透明的像素＝屋頂或物件頂。草皮、地面不算，所以只看 `y < FLOOR - 2`。換新建築時這張表會自動跟著變，不用手畫。
- **哪些雨會打到屋頂**：雨分前後兩層，前面那層（`Draw`）比房子近，照理打不到屋頂，所以**只讓後面那幾層（`DrawBack` 的近層）落在接雨面上**，前面那層照舊落到地上。
- **屋簷滴水**：接雨面高度往下掉很多（屋簷邊）的那幾欄，是滴水點。
  - 水滴一串一串往下掉，落地起漣漪。
  - 下面那一欄的地面積水先出現：`TownPuddles` 的門檻在那附近降低。
- **雨量與大小**：使用者 2026-11-19 說雨「太大」，要的是**少一點（密度）**，不是改雨絲長短或水花。已從 0.45 降到 0.25（`TownArt.DrawWeather` 傳進去的 `density`）。

## 4b. 水路與建築結構圖（2026-11-19，使用者確認過）

- **水路要照建築真正的結構流，不能只看剪影。** 只看剪影會：屋頂的水穿過牆、盾牌、門洞；香菇傘的水穿過菌褶。用「碰到黑色外框就停」也不行：這套美術的屋頂瓦片跟外框一樣暗。
- **結構圖**（手畫的資料）：每棟一張、跟建築原圖一樣大。顏色意思如下：

| 顏色 | 類別 | 意思 |
|---|---|---|
| 藍 | 屋頂面 | 水往下流 |
| 灰 | 擋雨區 | 不濕、水不經過 |
| 橘 | 繞開 | 水繞過去 |
| 黃 | 導水線 | 水沿著走 |
| 紅 | 滴水線 | 水流到這裡就滴 |
| 洋紅 | 滴水點 | 單獨會滴水的點 |
| 綠 | 接水面 | 上面滴下來的水打在這 |

  - 產生：`art/工具/場景/structure-maps.py`，每棟用位置＋顏色一段一段寫。
  - 給使用者看：`structure-review.py` 產生原圖與疊圖並排的總覽，加一張顏色說明。
  - 通過的放在 `art/3-已通過/town/structure/`，複製成 `unity/Assets/Resources/Art/town/structure/<名稱>.bytes`（PNG 改副檔名才能當 TextAsset 讀）。
  - **換建築的圖（`art/3-已通過/town/<名稱>.png` 改了）一定要重跑 `structure-maps.py`**：
    - 遊戲裡會自動對位，換了圖整體還是對得上，但外框差一格，雪和水路的起點會跑掉。
    - 新圖的顏色也可能讓用顏色判斷的地方失效。2026-11-19 新版旅館的菌褶多了粉色亮面和暗紅線，傘蓋的範圍一路漏到窗戶上面。
    - 重跑後檢查：結構圖和新圖的剪影要 0 格對不上；各類別的格數不能突然差很多；看疊圖確認，再複製到 `art/3-已通過/town/structure/` 和 `Resources/Art/town/structure/*.bytes`。
- **遊戲裡**：
  - `TownStructure.cs`：載入結構圖，用剪影在城鎮主圖層裡找位置（建築可能被擺放工具移動過），貼成世界座標的類別。
  - `TownFlow.cs`：算水路。
    - 有結構圖的建築：屋頂面上照流向流；繞開就從旁邊滑過去；導水線就一格一格沿著走；到滴水線、滴水點或擋雨區就滴。
    - 沒有結構圖的物件：自動，寬度突然變窄的那一列算屋簷。
    - 流向＝往下＋順著形狀往外張開＋**雜訊偏轉（±40 度，隨機但有範圍）**。種子 `TownFlow.Seed`，範圍 `RangeDeg`。
  - 滴水：水路滴下去的地方＋結構圖的滴水點，往下掉到接水面、屋頂、物件或地面。地面那幾點附近積水先出現。
  - 變濕分數：「離水路多近」（10 格）＋雜訊，所以先沿著彎的水路濕，再往兩邊擴散；擋雨區永遠不濕。**有結構圖的格子不要用「從頂往下、碰到空隙就停」**，不然小香菇、煙囪底下那幾欄會全黑。
  - 往下流的亮點：沿著水路走。世界資料 B＝走了多遠，A＝哪一條水路（shader 和 CPU 版都用）。
- **看圖**：
  - `SHOT_FLOW=1` 輸出 `flow.png`：結構圖淡淡疊上、青線水路、紅點滴、虛線落下、綠＝打在東西上、黃＝地上。
  - `score.png` 看變濕分數。
  - `SHOT_FLOWSEED`、`SHOT_FLOWRANGE` 換種子、範圍。

## 4c. 平台積水、地面折射、雨打在角色身上（2026-11-19）

- **平台積水**（`TownRainHits.Build` 找，shader 畫）：
  - 找朝上的平面，平的一段至少 4 格寬。
    - 結構圖的接水面取最上面那一列。陽台欄杆在牆前面，上面一格是牆，**不能要求上面是空的**。
    - 沒有結構圖的物件，取從天空看下來第一個面。
  - 水積在外框裡面那一列（寬 8 格以上兩列），兩頭各留一格；每一段要多濕才出現不一樣。
  - 世界資料記號：G＝120（不是 0 也不是 255）、R＝要多濕、B＝第幾列、A＝0。shader 在變濕那段之前先處理。
  - CPU 版只有水色與亮邊，沒有倒影。
- **地面折射**：積水的水底不再是固定的水色，改成「被漣漪和雜訊左右扭的草皮 × 偏藍偏暗」，近的列看得出隔著水看的扭曲。
- **雨打在角色身上**（`TownRainHits.DrawActors`，在 `DrawWeather` 裡、雨之前）：
  - 每格隨機挑 28 欄，從上往下找第一個不是場景、下面連續 3 格也不是的格子（頭頂、肩膀），機率命中就濺小水花。
  - 角色是舊的畫法，要先 `frame.ProtectLegacyDraws()` 才看得到角色在哪；呼叫兩次沒關係。
  - 只有顯示卡模式（有天氣遮罩）才做。

## 4d. 擴大碎星鎮、加新建築（2026-11-19 準備好）

天氣程式（積水、變濕、水路、結構圖、積雪、冰柱）都不再假設城鎮的大小和建築的數量：
- **寬高**：天氣檔案裡的 `TOWN_W`／`H` 是每次讀 `TownArt.TOWN_W`／`H` 的屬性，陣列在 Build 時照當時大小配。`TownArt` 把寬度改成變數也能用（`FLOOR` 還是常數，地面高度改了要另外看）。
- **建築位置**：`TownStructure` 讀 `Resources/Art/town/structure/` 裡**每一張**結構圖，用 `structure-art/<名稱>` 的建築原圖跟城鎮主圖層逐像素比對。
  - 在整個城鎮（上下各 40 格）找九成以上一樣的地方，**找到幾處貼幾處**：同一棟放兩次、移位置都會對上。
  - 每棟約 50 ms（1240 寬），城鎮變 4 倍寬約 0.2 秒。
  - 只看剪影會認錯（旅館的剪影整個塞得進工坊圓頂裡），所以一定要比像素。
- **顯示卡貼圖上限**：城鎮資料貼圖跟城鎮一樣寬。超過這台的 `SystemInfo.maxTextureSize`（有些手機 4096）就自動改用 CPU 版，記錄裡會寫。`PostFx.TownOnGpu(frame)`＝`ActiveFor`＋貼圖建得起來，城鎮的天氣程式都要看這個。
- **加一棟新建築**的步驟：
  1. 新建築的圖放進 `art/3-已通過/town/<名稱>.png`。
  2. 在 `art/工具/場景/structure-maps.py` 加一個函式，照那棟的樣子標屋頂面、擋雨區、繞開、導水線、滴水線、滴水點、接水面，再加進最下面的清單；跑 `structure-review.py` 給使用者看。
  3. 通過後複製：結構圖 → `art/3-已通過/town/structure/<名稱>.png` 和 `Resources/Art/town/structure/<名稱>.bytes`；建築原圖 → `Resources/Art/town/structure-art/<名稱>.bytes`。
  4. 用 `SHOT_FLOW=1` 看水路圖，記錄裡 `結構圖：名稱@x,y` 要列出這棟。
  - 沒做結構圖的建築也能用，只是照自動的做法：寬度變窄的地方當屋簷、只看剪影。
- **建築的圖換了**：原圖和結構圖兩份都要換，大小不一樣時記錄會警告，那棟會照自動的做法。
- **還沒處理、要注意的**：
  - 城鎮高度如果超過 255：每一欄的資料用 byte 存列數（接雨面、濕亮邊），要改格式。
  - 地面不平（有坡、有台階）：積水、地面積雪都假設地面是第 `FLOOR` 列。
  - 新的小物件不用做什麼，都是自動的。

## 5b. 錄實機影片（Unity Recorder）

- 使用者 2026-11-19：錄實機要用 **Unity 內建的錄影（Unity Recorder）**，不要錄螢幕。錄螢幕會被別的視窗擋住，錄到使用者桌面上的東西；也不要自己逐張截圖再接，會拖慢、漏格。
- 套件：`com.unity.recorder` **5.1.8**（5.1.2 在 Unity 6000.6 編譯不過：`GetInstanceID` 已經是錯誤）。
- 腳本：`Editor/RecordPlay.cs`。
  - 進 Play Mode，用 GameRoot 的自動玩（`-shot … -shotat 999999`），照 `TRACE_SCRIPT` 的場景、天氣、時間、按鍵自動玩。
  - Recorder 用固定影格時間（Constant＋Cap），錄滿 `REC_SECONDS` 秒就存成 MP4，然後關掉編輯器。
  - **使用者要 60 fps**（`REC_FPS` 預設 60）。
  - 遊戲時間要跟著影格走：`PixelScreen.FrameDt` 在錄影時（`Time.captureDeltaTime > 0`）用錄影的固定影格時間，平常用真實時間；`Time.unscaledDeltaTime` 不受錄影影響，用了的話影片裡的動作會偏快或偏慢。
  - 新的計時一律用 `PixelScreen.FrameDt`。驗證方法：同一段 30 fps、60 fps 各錄一次，同一秒的畫面要一樣。
  - 要開編輯器畫面，不能加 `-batchmode`。
  ```bash
  REC_OUT='C:\Users\USER\ZeroStarUnity\Golden\rec\<檔名>' REC_SECONDS=18 TRACE_SCRIPT='<腳本.json>' "/c/Program Files/Unity/Hub/Editor/6000.6.0f1/Editor/Unity.exe" -projectPath 'C:\Users\USER\ZeroStarUnity' -executeMethod ZeroStar.EditorTools.RecordPlay.Run -shot 'C:\Users\USER\ZeroStarUnity\Golden\rec\tmp' -shotat 999999 -logFile <log>
  ```
- 錄影用的腳本：複製 `game/tools/unity/unity-trace-script-town-rain.json`，改 `events`（例如 `[40,"d","KeyD"]`、`[330,"u","KeyD"]` 來回走）、`day`、`weather`、`ticks`。
- 檢查：抽幾格看主角的位置跟按鍵時間對不對得上（遊戲時間照影格走），再用 SendUserFile 傳給使用者。

## 5c. 下雪（2026-11-19，`Runtime/Town/TownSnow.cs`）

- **天氣**：`TownArt.SnowK()` 是下雪量，換天氣時跟雨一樣慢慢過渡；`WX_PICK` 有一格是下雪；`SHOT_WEATHER=snow`。
- **雪花**（`DrawFlakes`，在角色之後）：三層，都是時間的函式，不用存粒子。
  - 遠：1 格的點，在空中淡掉。
  - 中：9 種 3×3 形狀隨機挑，在 0 度和 90 度之間換。**要一小團一小團的**，十字、X 形在天空裡太像星星。
  - 近：少數幾片雪花結晶，帶一點光（pixelfx snow 的畫法）。
  - 全部跟著風、陣風飄，開頭淡入、結尾淡出；中、近的落地後亮一下再消失。
- **積雪**（`DrawCover`，場景畫完、`BeginWeatherMask` 之前，所以角色站在雪前面）。三層：
  1. **地面**：每一欄都有。上面有路燈、燈串、招牌、建築也一樣，**不能只看「從天空看下來第一個面」**，不然 1240 欄只剩 247 欄有雪。最厚 9 格，蓋滿草皮帶，下緣不整齊往下垂；草葉從雪裡冒出來。
  2. **物件頂面**：從天空看下來第一個面，地面附近 12 格內算地面。
     - 平的堆得厚（6 格）、斜的薄、太陡和 1 格寬的尖端堆不住；擋雨區不積。
     - 厚了高出輪廓一格，外面補一圈黑外框（外框只能黑）。
  3. **結構圖的屋頂面整面**：越靠近頂端越早被雪蓋，加上雜訊一塊一塊往下長。
     - 原本暗的線（瓦片縫）留成雪的陰影，黑色外框不碰。
     - 積雪最多時門檻 0.4：下半部、邊緣還看得到原本的顏色。不然香菇傘會整顆變白，認不出來。
- **積雪程度**：下 60 秒積滿、停 120 秒融化；進場時照現在的雪直接設好；`SHOT_SNOW` 可以指定。
- **顏色**：白天白（陰天的白天也要白：白天程度 ×1.6）、晚上偏藍。燈光從光的緩衝加上去，路燈照得到雪。
- **屋頂面的雪不能出現尺畫的直線**（2026-11-19 使用者指出公會屋頂的直線）：
  - 「離天空多遠」不能只看這一欄的頂面：煙囪、水晶旁頂面突然跳，雪被切出垂直線。改成往左右各看 12 欄、斜著算（每欄 0.7）。
  - 頂上是繞開的東西（煙囪、水晶）的那幾欄，屋頂線用左右兩邊連起來補。從它下面開始算會切出方塊，整段跳過又會讓寬的水晶周圍一大塊沒雪。
  - 煙囪在結構圖裡標成繞開：直立的面雪不黏，頂上由頂面那層積。
  - 陡的面（看左右各 4 欄的坡度，只看隔壁會被青苔凸起騙）雪少，不然圓頂兩側會一路白到底。
  - 雜訊用真正的二維雜訊；一維雜訊斜著拉，邊界會變成斜直線。
  - 頂面那層雪厚度隨欄變化，不然平的屋脊下緣是一條水平線；有結構圖的屋頂頂面最多 3 格。
- **屋頂面的雪留縫的規則**：只留真的很暗的縫（亮度和 < 170，瓦片縫）。
  - 用 < 260 的話，香菇傘外緣那圈暗紅陰影會變成雪裡一條跟著輪廓的線，使用者不喜歡。
  - 頂面那層雪下面也是雪就不畫陰影列，雪塊下緣加一圈陰影。
- **冰柱**：長在水路的滴水點（地面附近的不算），每根最長 2～6 格。下雪時就長，長度跟著積雪程度；上粗下細、左亮右暗、尖端白、外框黑。
- **融雪**：雪停後融化，下雨融得更快。
  - 雪變成灰一點的雪泥。
  - 融掉的量從 `TownPuddles.MeltIn` 變成地上的積水，雪融完約積到八成。
  - 屋簷跟著滴水（濕度上來，滴水就開始）。
- **之後可以加**：腳印。

## 6. 混合畫面：CPU＋shader（2026-11-19 起；架構經使用者另一個 AI 審查後改過，照這版做）

使用者決定用「混合」：主畫面照舊 CPU 算，**整片逐格的效果（倒影、變濕、折射、霧、發光、水面）放到顯示卡**。不要整個改成 shader。

- **檔案**：
  - `Runtime/PostFx.cs`：城鎮資料貼圖、參數、`Resolve`／`Present`、`ActiveFor`。
  - `Runtime/FramePresentation.cs`：合成→上傳→`PostFx.Resolve`，每個顯示端各自持有貼圖。
  - `PixelFX/Painter.cs` 的 `Frame`：天氣遮罩。
  - `Resources/Shaders/PostFx.shader`：效果本體。
  - `Resources/Shaders/ScreenShow.shader`：把結果畫到螢幕。
- **每格自己決定要不要用顯示卡**：
  - `new Frame(...) { UseGpuWeather = true }`：PixelScreen、WeatherShot 的顯示卡模式、編輯器預覽。
  - CPU 端一律看 **`PostFx.ActiveFor(frame)`**：true＝只準備資料、不逐格畫；false＝CPU 自己畫（備用版）。
  - 不要用全域的開關（舊的 `PostFx.Use`／`Active` 已經拿掉）。
- **場景遮罩**（`frame.WeatherMask`，跟 `Color` 一樣大，255＝場景）：
  1. 場景畫完（`TownArt.Draw` 最後）：`if (PostFx.ActiveFor(frame)) frame.BeginWeatherMask();`，記下畫面，遮罩全部設成場景。
  2. 之後**每個會蓋在場景上的寫入都要 `frame.ExcludeWeather(i)`**：水珠、滴水、水花（`Px`）、前景草葉、畫筆（Painter 已經做了）。
  3. `DrawFg` 開頭 `frame.ProtectLegacyDraws()`：還在直接寫 `Color` 的舊角色和特效，跟記下的畫面比，被改過的格子扣掉。
  - 四角壓暗只改亮度，不改遮罩。
  - 新程式**一定要自己呼叫 `ExcludeWeather`**，不要靠 `ProtectLegacyDraws`。
- **這一格的資料準備好了**：TownPuddles 在 `ActiveFor` 時寫好每欄資料、漣漪、參數，再設 `frame.WeatherReady = true`。
  - `PostFx.Resolve` 只在 `WeatherReady && TrackingWeather && ActiveFor && 有城鎮資料` 時跑 shader，不然直接回傳原本的貼圖。所以換到關卡會自動原樣輸出。
- **給 shader 的資料**：
  - 遮罩（加上四周補的一格）。
  - 每一欄的資料（城鎮寬×1）：R 積水深度，每格更新；G 接雨面；A 濕亮邊列。
  - 世界座標的資料（城鎮寬×高）：R 變濕分數、G 不會濕、B 沿著水路走了多遠、A 哪一條水路。
  - 參數：`_Cam`（鏡頭、時間）、`_Env`（濕度、白天、地面 y）、`_Rip[32]`（漣漪）。
- **座標**：
  - 貼圖第 0 列＝畫布第 -1 列（上面補的一格），所以 `cx = floor(uv.x*寬) - 1`、`cy = floor(uv.y*高) - 1`，加上 `_Cam.xy` 就是世界座標。
  - 一律以整格計算，取樣用格子中心（`(c + 1.5) / 寬`）、最近點。
  - 色彩空間是 Gamma，數值直接照 CPU 版的 0～255 / 255。
- **資源釋放**：PostFx 自己的貼圖、材質在換程式（assembly reload）和關閉時釋放（`ReleaseSharedResources`）。顯示端的 RenderTexture 由 `FramePresentation.Dispose` 釋放。
- **測試**：
  - `Editor/WeatherPresentationTest.cs`：天氣顯示的測試。
  - `WeatherShot` 預設用顯示卡（`SHOT_GPU=0` 強制 CPU）。要用顯示卡就不能加 `-nographics`。
  - 比對：同一版程式 CPU 與顯示卡各截一張，算不同的格子數。2026-11-19 結果：整張約 150～460 格不同，都是雜訊花紋。
- **加新效果**：
  1. 在 PostFx 加資料；靜態的放世界貼圖或每一欄的貼圖，動態的放參數。
  2. 在 PostFx.shader 加一段，先用世界座標的 y 範圍或遮罩 early return。
  3. CPU 端：`ActiveFor` 時只準備資料；會蓋在上面的小東西自己 `ExcludeWeather`。
  4. 補上 CPU 備用版。
  5. 顯示卡、CPU 兩種都截圖確認。
