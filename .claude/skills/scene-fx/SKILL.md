# scene-fx：場景環境特效

從 2026-11-17 做碎星鎮雨天積水開始累積。每條規則後面有「為什麼」。**畫圖、做特效還是要先載入 pixelfx skill，照它的「畫→看→修」至少三輪。**

## 0. 先知道的事

- **畫面主體是 CPU 算的，重的逐格效果交給 shader（混合，見 §6）。** 每格畫進 `Frame`（`unity/Assets/Scripts/PixelFX/Painter.cs`）：
  - `Color`：顏色（不透明）。
  - `Light`：加上去的光。讀寫前它會先把還沒畫的光暈畫完。
  - `Ox`、`Oy`：鏡頭位置。世界座標要減掉它們才是畫面座標。
  - 解析度 384×216，城鎮地面 `TownArt.FLOOR = 184`。
- **影片裡的東西怎麼換：**
  - Godot 的 SubViewport／螢幕貼圖：先 `Array.Copy` 一份 `Color`／`Light`，再從那份取樣（`TownPuddles` 的 `srcC`、`srcL`）。
  - shader 的 step()：每一欄或每一格算一個門檻，比大小。
  - GPU 粒子：自己用 List 存的小粒子，或 pixelfx 的純函式迴圈特效（`Fx/TownRain.cs`）。
- **橫向卷軸，不是俯視。** 影片多半是俯視角，地面是一大片。我們的地面只是一條 6 列高的草皮帶（城鎮第 185～190 列），從側面看：
  - 積水＝草皮帶上扁扁的橢圓，中間厚、兩頭收成一條線。
  - 倒影＝把地面上方的畫面翻過來、**壓扁**（`SQUASH` 約 2.6）。不壓扁的話，6 列只映得到腳底。
  - 漣漪＝從側面看到的環＝兩小段往左右滑開（pixelfx weather/rain 的 `rings`）。
- **只做 Unity 版、不比對網頁版**（2026-11-12 起）。新特效寫在 `unity/Assets/Scripts/Runtime/…`，檔頭註明「Unity 版自己的」。
- **畫的順序**在 `Game.cs` 的 Step 繪圖段：場景 → 怪 → 主角 → 前景特效 → `TownArt.DrawWeather`（雨 → 積水）→ `DrawFg` 前景草葉、四角壓暗。
  - 要映出角色的東西（倒影），一定要畫在角色之後。
  - 會被霧蓋掉的東西，要畫在霧之後。
  - 雨的貼地薄霧使用者說效果不好，已經取消（2026-11-19），不要再加回去。

## 2. 積水（已做，`Runtime/Town/TownPuddles.cs`）

- **形狀**：`Field(x)` 是兩層一維雜訊，門檻 `thr = 0.74 - 0.27 * wet`，下滿雨約 4 成地面有水。
  - 深度＝(雜訊 − 門檻) / 0.15。除數太小，水窪兩頭會收得太硬。
- **濕度 `wet`**：
  - 下雨約 40 秒積滿，雨停約 90 秒乾掉。
  - 進場時（`Reset` 後第一格）直接等於現在的雨量。不然玩家一進城鎮看不到積水。截圖工具也要在設好天氣之後 `TownPuddles.Reset()`。
- **倒影**：越遠的列反射越多，越近的列越看得到水底（比較暗）。漣漪附近左右晃，晚上把 `Light` 一起映進水裡（路燈、窗戶）。
- **邊**：
  - 遠邊：亮邊，跟著兩層移動雜訊斷斷續續。只用一層高頻雜訊的話，會變成規則的虛線，很死板。
  - 遠邊還有滑動的反光點。
  - 近邊：暗線。
  - 水窪底下一列草皮壓暗。
- **踩水**：`TownPuddles.Player` 每格由 Game 叫。在水裡每走 9 px 起一圈大漣漪，濺起 4～6 顆水珠。

## 3. 慢慢變濕、積雪（照影片 05 的雪，再加上水會流）

**同一套遮罩：** `濕(x, y) = 雜訊(x, y) + 偏移 > 門檻(wet)`。門檻隨濕度往下降，就會從「幾點」長成「一片」。雪是堆積，水會流，所以偏移不一樣：

- **雪**：朝上的面最先積，偏移＝「朝上程度」。往上那格是空的，這格就是朝上的面。
- **水**：
  - 從受雨的頂面開始（偏移最大），沿著牆往下越來越淡，所以要減掉「離頂面的距離 × 斜率」。
  - 雜訊在 y 方向拉長（例如 x/3、y/12），看起來是往下流的水痕，不是一團一團。
  - 屋簷、凸出的邊下面那幾格多加一點（水從那裡滴下去）。
- **雪與濕的樣子**：
  - 濕：原色變深一點、飽和一點，朝上的邊加一條濕亮的反光。
  - 雪：直接換成雪色，邊緣用 2 色階。
  - 都要像素化：遮罩以整格計算，不用半透明漸層。
- **效能（手機要跑）**：
  - 遮罩只跟「濕度」和「靜態圖層」有關。建築圖層載入時算一次「頂面距離」「朝上程度」存成 byte 陣列；濕度每變 1/32 才重算遮罩（存 byte 陣列），平常每格只查表。
  - 每格的迴圈只跑畫面內的那幾欄；不要每格 new 陣列（`Prof.Bytes` 會記暫存）。
  - 整個畫面的逐格運算用 `PixelFX.Par.For(8, …)` 切 8 段，每段只寫自己的列。

## 4. 雨跟房子、物件互動

- **已做（`Runtime/Town/TownRainHits.cs`，2026-11-19）踩到的坑**：
  - 從頂面往下算「淋得到」時，碰到**短的空隙**（屋頂上的小香菇、圖裡 1～2 格的縫）不能當成被擋住，否則會整條直的不濕，看起來一條條色差；空隙 6 格以內跳過去，長的才算屋簷下。
  - **外框（暗色，RGB 加起來 < 150）不碰**：濕亮邊畫在頂面往下第一個不是外框的像素，不然會把黑色外框改成亮色（違反「外框黑」）。
  - 變暗不要太多（×0.87 左右，飽和 ×1.12），不然整棟像晚上。
  - 濕度跟積水共用 `TownPuddles.Wet`，所以地上和房子一起濕、一起乾。
  - 除錯：`WeatherShot` 會輸出 `score.png`（世界座標的變濕分數，紅線＝接雨面），用來找「哪幾欄為什麼不濕」。`SHOT_WET=0.25`／`0.55`／`1` 看慢慢變濕。


- **接雨面**：載入時從建築圖層（城鎮 `MAIN`）每一欄由上往下找第一個不透明的像素＝屋頂或物件頂。草皮、地面不算，所以只看 `y < FLOOR - 2`。換新建築時這張表會自動跟著變，不用手畫。
- **哪些雨會打到屋頂**：雨分前後兩層，前面那層（`Draw`）比房子近，照理打不到屋頂，所以**只讓後面那幾層（`DrawBack` 的近層）落在接雨面上**，前面那層照舊落到地上。
- **屋簷滴水**：接雨面高度往下掉很多（屋簷邊）的那幾欄，是滴水點。
  - 水滴一串一串往下掉，落地起漣漪。
  - 下面那一欄的地面積水先出現：`TownPuddles` 的門檻在那附近降低。
- **雨量與大小**：使用者 2026-11-19 說雨「太大」，要的是**少一點（密度）**，不是改雨絲長短或水花。已從 0.45 降到 0.25（`TownArt.DrawWeather` 傳進去的 `density`）。

## 4b. 水路與建築結構圖（2026-11-19，使用者確認過）

- **水路要照建築真正的結構流，不能只看剪影。** 只看剪影會：屋頂的水穿過牆、盾牌、門洞；香菇傘的水穿過菌褶。用「碰到黑色外框就停」也不行：這套美術的屋頂瓦片跟外框一樣暗。
- **結構圖**（手畫的資料）：每棟一張、跟建築原圖一樣大。顏色意思如下：

| 顏色 | 類別 | 意思 |
|---|---|---|
| 藍 | 屋頂面 | 水往下流 |
| 灰 | 擋雨區 | 不濕、水不經過 |
| 橘 | 繞開 | 水繞過去 |
| 黃 | 導水線 | 水沿著走 |
| 紅 | 滴水線 | 水流到這裡就滴 |
| 洋紅 | 滴水點 | 單獨會滴水的點 |
| 綠 | 接水面 | 上面滴下來的水打在這 |

  - 產生：`art/工具/場景/structure-maps.py`，每棟用位置＋顏色一段一段寫。
  - 給使用者看：`structure-review.py` 產生原圖與疊圖並排的總覽，加一張顏色說明。
  - 通過的放在 `art/3-已通過/town/structure/`，複製成 `unity/Assets/Resources/Art/town/structure/<名稱>.bytes`（PNG 改副檔名才能當 TextAsset 讀）。
  - 換建築的圖，要回來改腳本、重跑、給使用者看。
- **遊戲裡**：
  - `TownStructure.cs`：載入結構圖，用剪影在城鎮主圖層裡找位置（建築可能被擺放工具移動過），貼成世界座標的類別。
  - `TownFlow.cs`：算水路。
    - 有結構圖的建築：屋頂面上照流向流；繞開就從旁邊滑過去；導水線就一格一格沿著走；到滴水線、滴水點或擋雨區就滴。
    - 沒有結構圖的物件：自動，寬度突然變窄的那一列算屋簷。
    - 流向＝往下＋順著形狀往外張開＋**雜訊偏轉（±40 度，隨機但有範圍）**。種子 `TownFlow.Seed`，範圍 `RangeDeg`。
  - 滴水：水路滴下去的地方＋結構圖的滴水點，往下掉到接水面、屋頂、物件或地面。地面那幾點附近積水先出現。
  - 變濕分數：「離水路多近」（10 格）＋雜訊，所以先沿著彎的水路濕，再往兩邊擴散；擋雨區永遠不濕。**有結構圖的格子不要用「從頂往下、碰到空隙就停」**，不然小香菇、煙囪底下那幾欄會全黑。
  - 往下流的亮點：沿著水路走。世界資料 B＝走了多遠，A＝哪一條水路（shader 和 CPU 版都用）。
- **看圖**：
  - `SHOT_FLOW=1` 輸出 `flow.png`：結構圖淡淡疊上、青線水路、紅點滴、虛線落下、綠＝打在東西上、黃＝地上。
  - `score.png` 看變濕分數。
  - `SHOT_FLOWSEED`、`SHOT_FLOWRANGE` 換種子、範圍。

## 5. 畫→看→修（一定要做）

- **截圖**：`unity/Assets/Scripts/Editor/WeatherShot.cs`，不用開編輯器。
  ```bash
  "/c/Program Files/Unity/Hub/Editor/6000.6.0f1/Editor/Unity.exe" -batchmode -nographics -projectPath 'C:\Users\USER\ZeroStarUnity' -executeMethod ZeroStar.Tests.WeatherShot.Run -quit -logFile <log>
  ```
  - 環境變數：
    - `SHOT_WEATHER`：rain／cloudy／clear。
    - `SHOT_DAY`：0.25＝中午、0.75＝半夜。
    - `SHOT_TICKS`：第幾步截圖。
    - `SHOT_X`：主角起點。
    - `SHOT_WALK`：第幾步開始往右走。
    - `SHOT_WET`：進場時的濕度（0～1），看慢慢變濕的過程。
    - `SHOT_OUT`：輸出資料夾。
  - 輸出在 `unity/Golden/weather/`（git 不追蹤），每張放大 3 倍。
  - Unity 不接受中文路徑，所以 `-projectPath` 用英文 junction。
- **看的時候**：
  - 整張看一次，再把地面那條（第 140～216 列）最近鄰放大 3～8 倍看細節。
  - 讀圖工具可能拿到舊的快取：每一輪輸出到新的資料夾（r1、r2…）再讀。
- **固定要看的幾種**：
  1. 白天全畫面。
  2. 晚上全畫面（倒影裡要有燈光）。
  3. 主角走過最大一攤水的連續 4 張（`SHOT_X=380 SHOT_WALK=20 SHOT_TICKS=60,64,68,72`；城鎮 x 355～490 是一攤大水窪）。
  4. 濕度剛開始、一半、滿（看會不會突然跳出來）。
  5. 雨停之後乾掉。
- **常見問題**：

| 看到 | 修 |
|---|---|
| 完全看不到 | 先確定濕度不是從 0 慢慢長（截圖工具要 Reset）；是不是被霧或前景蓋住 |
| 跟地面分不開 | 水底色壓暗、反射加強；遠邊亮邊、近邊暗線、底下壓暗 |
| 邊像規則虛線 | 換兩層不同速度的雜訊，門檻提高讓亮邊變長段 |
| 水窪兩頭像被切斷 | 深度的除數加大（漸變長一點） |
| 一進場突然冒出來 | 進場照現在的天氣設好濕度 |

- **給使用者看**：全畫面一張＋地面放大一張，用 SendUserFile 傳。使用者用手機看，說明用繁體中文短句。測過沒問題就 commit＋push，不用問；只 commit 自己改的檔案，資料夾裡別人還沒 commit 的改動不要一起加。

## 6. 混合畫面：CPU＋shader（2026-11-19 起）

使用者決定用「混合」：主畫面照舊 CPU 算，**整片逐格的效果（倒影、變濕、折射、霧、發光、水面）放到顯示卡**。不要整個改成 shader。

- **檔案**：
  - `Runtime/PostFx.cs`：底層，管資料、遮罩、上傳、Blit、顯示。
  - `Resources/Shaders/PostFx.shader`：效果本體。
  - `Resources/Shaders/ScreenShow.shader`：把結果畫到螢幕。
  - shader 放在 Resources，才會被打包進遊戲。
- **一格的流程**：
  1. CPU 畫場景。
  2. `PostFx.MarkScenery`：記下場景。
  3. 畫角色、特效、雨。
  4. `DrawFg` 開頭 `PostFx.BuildMask`：跟記下的場景比，沒被改過的格子＝場景。
  5. 前景草葉畫完 `PostFx.FinishMask`：前景蓋到的格子扣掉。
  6. 四角壓暗 → 合成 → 上傳貼圖。
  7. `PostFx.Present`：Blit 跑 PostFx.shader 到 RenderTexture，SpriteRenderer 換成 ScreenShow 材質顯示。
  - 遮罩一定要在四角壓暗之前算，不然畫面邊緣整圈都會被當成「不是場景」。
- **給 shader 的資料**：
  - 遮罩：跟畫面一樣大，含四周補的一格。
  - 每一欄的資料（城鎮寬×1）：R 積水深度每格更新；G 接雨面、B 水痕種子、A 濕亮邊列，這三個是靜態的。
  - 世界座標的資料（城鎮寬×高）：R 變濕分數、G 不會濕，靜態。
  - 參數：`_Cam`（鏡頭、時間、是否城鎮）、`_Env`（濕度、白天、地面 y）、`_Rip[32]`（漣漪）。
  - `TownFrame` 每格要重新設，沒設就原樣輸出（換到關卡自動沒有效果）。
- **座標**：
  - 貼圖第 0 列＝畫布第 -1 列（上面補的一格），所以 `cx = floor(uv.x*寬) - 1`、`cy = floor(uv.y*高) - 1`，加上 `_Cam.xy` 就是世界座標。
  - 一律以整格計算，取樣用格子中心（`(c + 1.5) / 寬`）、最近點。
  - 色彩空間是 Gamma，數值直接照 CPU 版的 0～255 / 255。
- **CPU 備用（一定要保留）**：
  - `PostFx.Active`＝有顯示卡＋有人負責顯示（`PostFx.Use`，PixelScreen 和 WeatherShot 會設）＋shader 能用＋`Enabled`。
  - `Active` 是 false 時，CPU 照舊自己畫。自動測試（`-nographics`、TraceTest）都走 CPU 版。
  - 新效果：CPU 端在 `Active` 時只準備資料、不逐格畫；不是 `Active` 時用 CPU 版，或乾脆不畫。
- **CPU 端還是要畫的**：會蓋在水面上面的小東西（水珠、雨滴、屋簷滴水），因為它們不是場景，shader 不會改到。
- **截圖**：
  - `WeatherShot` 預設用顯示卡（`SHOT_GPU=0` 強制 CPU）。
  - 要用顯示卡就**不能加 `-nographics`**。
  - 比對：同一版程式 CPU 與顯示卡各截一張，算不同的格子數（2026-11-19 首次：整張 150～458 格不同，都是雜訊花紋），再並排看。

  1. 在 PostFx.cs 加資料；靜態的放世界貼圖或每一欄的貼圖，動態的放參數。
  2. 在 PostFx.shader 加一段（先用世界座標的 y 範圍或遮罩 early return，其他格子不要多算）。
  3. 補上 CPU 備用版。
  4. 顯示卡、CPU 兩種都截圖確認。
