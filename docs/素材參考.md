# 素材參考紀錄

規則：製作素材前先找多個參考（不能只找一個），並遵守 `終極版規則v2.txt` 與 PixelFX skill。
參考只用來學做法（構圖、明暗、階梯、配色邏輯），不照抄任何一張圖。來源大多是 OpenGameArt.org。

## 場景層次感與光影（2026-11-03，使用者指定參考絲之歌、Ori）
只借「技法」，不模仿這兩款遊戲的畫面、角色或場景造型。它們是手繪高解析度畫面，搬到像素畫要遵守規則v2（不模糊、不柔邊），所以每個技法都換成像素做法。

| 參考 | 看到的技法 | 換成像素做法 |
|---|---|---|
| 絲之歌 Steam 截圖×4 | 每一區有一個主色光（琥珀、綠、藍、灰綠）；越遠越接近霧的顏色；前景有近乎全黑的剪影框住畫面；光束從上方斜照下來；漂浮的光點 | 每層的色票預先往霧色混合（固定色，不漸層）；前景剪影層（比主角近，視差 >1）；光束做成硬邊的 2～3 段亮度帶 |
| Ori Steam 截圖×4 | 遠處最亮（逆光），近處最暗；冷色場景配暖色光源；平台頂邊有邊緣光；角色本身會發光照亮周圍；畫面四角暗 | 背景中段放一條亮的霧光帶；藍綠色洞窟＋橘色火把；地面頂邊加一階亮；主角、火球、爆炸、水晶都是光源；四角暗一階 |
| Hollow Knight / Ori 美術分析文章 | 三層以上：前景、遊玩層、背景；遊玩層對比最高、外框最清楚；遠景少細節 | 6 層：天空霧光、遠景、中遠景（巨大垃圾剪影）、中景（水晶、鎖鏈）、遊玩層、前景剪影 |
| SLYNYRD Pixelblog 23（像素視差教學） | 遠層慢、近層快，速度間距要有規律；整數像素移動；靜止時就要有深度感（大氣透視） | 視差 0.05 / 0.12 / 0.3 / 0.6 / 1 / 1.35；所有層都在整數格上 |

**光影系統（讓場景受光效影響）**：每個環境像素記錄「材質＋明暗階」，光源照到時明暗階往上加（一圈一圈分階，不做平滑漸層），所以亮起來的顏色還是色票裡的顏色。

來源：
[Polycount 對 Ori 霧與景深的討論](https://polycount.com/discussion/comment/2101739)、[Airborn Studios：Ori](https://airborn-studios.com/projects/ori)、[The Art of Hollow Knight](https://medium.com/3d-environmental-art/the-art-of-hollow-knight-f4c05dda3882)、[Hollow Knight 視覺設計分析](https://halabaojia.pages.dev/collection/20251111-hollow-knight-visual-design-analysis)、[SLYNYRD Pixelblog 23](https://www.slynyrd.com/blog/2019/11/12/pixelblog-23-parallax-scrolling)、Steam 商店頁截圖（[絲之歌](https://store.steampowered.com/app/1030300/)、[Ori](https://store.steampowered.com/app/387290/)）

## 大招「零星墜落」（2026-11-03）
使用者更正：特效與場景光不受規則v2限制（可用柔光、漸層、半透明）；規則v2只管我畫的角色與怪物。場景光因此改成柔和衰減。

| 參考 | 學到的做法 | 用在哪 |
|---|---|---|
| 格鬥遊戲的超必殺演出（Packt《The Big Finish》、TV Tropes「Super Move Portrait Attack」、MUGEN SuperPause） | 放招瞬間全場停住、畫面變暗、角色特寫插入，把注意力集中在招式上 | 起：暗場＋世界停住；承：下方特寫帶 |

| PixelFX：arcane/rune-circle、holy/sunburst、impacts/ground-slam、arcane/star-fall（直接使用、改金色） | 法陣、放射光、落地衝擊、星屑 | 起、承、合 |
| PixelFX：arcane/time-stop、magic-circle-cast、holy-pillar、explosions/nuke、lightning/charge-up（只參考） | 時間停止的節奏、光柱、全白一閃、集氣粒子往中心吸 | 自己做的集光粒子、星核、墜落的星星、衝擊波 |

## 主角改成立體多角星（金色水晶）（2026-11-03）
使用者提供摺紙立體星（星形八面體）照片；要求：尖角就是手、金色水晶、不用眼睛改用中心光點表情、拿掉領巾改用別的識別特徵、要做轉身。
| 參考 | 學到的做法 |
|---|---|
| 使用者提供的摺紙立體星照片 | 兩個三角錐交叉；正面看是六角星，中心是最靠近鏡頭的尖點，所有面在那裡交會 |
| [Wikimedia Commons：Stellated octahedron](https://commons.wikimedia.org/wiki/Category:Stellated_octahedron) | 幾何結構（立方體 8 個角分成兩組三角錐） |
| PixelFX pickups/gem-spin | 寶石轉動時，亮面跟著移動，看起來就是立體的 |
| PixelFX pickups/crystal-shard | 金色水晶配色、光從內部透出來 |
| [Clip Studio：Coloring Gems and Crystals](https://tips.clip-studio.com/en-us/articles/14881)、[r/PixelArt 寶石畫法討論](https://reddit.birdcat.cafe/r/PixelArt/comments/1i0sqcm/how_i_draw_gemstone_sprites) | 面朝光最亮、背光面最暗；稜線加高光把面分開；寶石可以用比一般物體多的明暗階 |

草稿：`game/tools/drafts/crystal-star.mjs` → `docs/主角草稿-立體水晶星.png`（D1 標準六角、D2 下角收平、D3 收平＋青色光點；下排轉身 5 格）。
- 2026-11-03 使用者回饋：「型態不太對」、「還是要有眼睛」。原因：第一版用平行投影，前後的尖角一樣大，看起來像平面的六芒星。修正：用 `fit-view.mjs` 對照片 7 個尖角位置擬合觀看角度，加上透視（前面的左、右、下三個尖角大，後面的上、左下、右下三個小），眼睛是貼在 3D 面上的點，轉身時跟著轉。
- 2026-11-03 使用者決定退回五角星版本（胖星 B1，`game/src/star.js`）。立體水晶星草稿（`crystal-star.mjs`、`fit-view.mjs`）留在 drafts 當紀錄，不使用。
